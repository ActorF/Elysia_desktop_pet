## 本地聊天与记录

- 托盘新增 **打开聊天框**。聊天窗口可单独移动、调整大小和关闭，关闭后桌宠继续运行。
- 输入框支持 Enter 发送、Shift + Enter 换行；中文输入法选词不会误发。回答逐步显示，可随时停止生成。左上加号新建对话，底部齿轮打开设置与记录。
- 默认连接 `http://localhost:11434`，使用 `tobestyledintro/qwen3.8-9b-distill:latest`。用户名可在设置中修改，高级选项支持其他 Ollama 地址与模型。已有自定义连接不会被自动配置覆盖。
- 人设 system prompt 保存在仓库 [electron/chat-persona.md](../../electron/chat-persona.md)，随程序一起打包。
- 用户消息下方提供复制按钮；爱莉希雅回复下方提供复制和单条朗读按钮。图标在悬停或键盘聚焦时显示说明。
- 设置共七页：外观、动画、桌面、互动、语音、聊天、聊天记录。历史页使用左侧会话列表、右侧消息详情，可继续对话，删除单段或清空全部记录；删除需确认，保留用户名及其他设置。
- 聊天记录保存在 `%APPDATA%/Elysia Desktop Pet/chat-state.json`，历史消息保留发送时的用户名。流式更新不会打断已完成文本的选取和复制。

## 回复朗读与音频互斥

**自动朗读默认关闭。** 普通文字聊天不会加载声音模型；点击回复下的朗读图标可单独播放这一条，不改变自动朗读开关。开启自动朗读后可提前预热，并在整条回答生成完毕后朗读。

同情绪模型可短时复用，空闲 45 秒释放。最近最多 8 条、合计不超过 24 MiB 的音频只在内存中缓存，重复朗读可直接播放；删除聊天记录会清除缓存。根据正文线索选择已有情绪参考，否定或不明确的表达回到中性，不调用额外的情绪分类大模型。

当前机器的 CPU 实测：冷启动或切换情绪约 **25 秒**，同情绪暖模型的新回答约 **1.8–2.4 秒**开始出声。缓存命中无需重新合成。这些是本机测量值，不代表所有电脑的速度。

发送新消息或点击停止会停止当前朗读；关闭聊天、关闭自动朗读或退出会释放声音模型。朗读遵循“语音”页的音量和勿扰设置，期间暂停日常与点击录音，点击仍可显示表情和静默字幕。旧的待播回应及迟到回调不会恢复播放。

## 首次自动配置

首次运行打包程序时自动打开聊天设置并开始准备环境，无需手动输入原项目路径或运行安装命令。聊天模型与语音环境显示各自的进度、就绪状态、取消和失败重试；Ollama 正在安装时不能取消。普通打开设置只检查状态，不重复启动安装。

| 资源 | 准备方式 |
| --- | --- |
| Ollama | 检测已有安装；需要时自动下载安装并启动服务 |
| 默认 Qwen 聊天模型 | 通过 Ollama 下载，约 6.7 GB |
| 独立 Python、爱莉希雅语音权重与配置 | 约 246 MB，随程序携带 |
| GPT-SoVITS 运行环境 | 从固定上游来源下载，约 5.7 GB |

语音环境部署到用户数据目录的 `voice-runtime`；高级设置仍可选择已有的兼容环境。语音资源按固定 SHA256 校验后部署，并验证环境结构；失败不会显示为已就绪。准备、解压和校验不启动声音模型，也不会自动开启朗读。取消后可重试并复用已校验资源。

源码运行不会自动启动首次下载，可在聊天设置中配置，或连接已有服务。构建语音资源时不包含个人 `.env`、聊天数据库或未授权的角色素材。

## 身体部位互动

整合 PR #6 及本地拾取修正，按实际角色图像区分头部、脸部、手部、身体、腿部和道具，范围随四种动作、待机摆动和缩放变化。透明间隙、可见按键云朵和睡眠／眩晕装饰不触发角色点击；拖动期间使用最后实际绘制的遮挡位置。

| 点击部位 | 普通表情 |
| --- | --- |
| 头部、脸部、手部 | 害羞、Wink、爱心眼、微笑中随机选择 |
| 身体、腿部 | 惊讶、害羞中随机选择 |
| 道具 | 微笑 |

普通表情持续约 **1.8 秒**，期间的点击继续计数，但不重新随机、不延长表情、不重复请求普通语音。各部位共用计数，**3 秒内第 5 次点击优先触发生气**，可打断普通表情；生气持续约 2.6 秒，点击冷却为 3 秒。临时表情结束后恢复原表情，手动选择表情优先于旧计时器。

仍使用摸头、戳戳、生气三组已确认的互动录音，没有新增录音或试听入口。拖动、长按、右键滚轮和透明空白不计入轻点；关闭点击互动会清除当前反应及计数，同时保留拖动缩放。

## 置顶修复

在 Windows 上，副屏任务栏有时仍带有“置顶”标志，实际却排在普通程序后方。此前桌宠只要被放到这个任务栏后面，也会一起落到普通窗口后方；其他独立置顶程序覆盖后，原有维护逻辑也可能未能恢复正确顺序。

1.4.1 检查实际窗口顺序，在“始终置顶＋任务栏在前”时恢复 **任务栏 → 桌宠 → 普通应用** 的前后关系，并处理外部置顶应用造成的遮挡。修复仅校正当前可见且已置顶的真实 Windows Shell 任务栏与自有窗口的 Z 顺序，保持任务栏位置、尺寸、可见性和当前输入焦点。不会强行显示隐藏任务栏或提升被系统取消置顶的任务栏。

保留字幕、流光等辅助窗的前后顺序，并在关闭置顶或切换模式后恢复当前设置。

适用范围是普通 Windows 桌面，不承诺覆盖安全桌面、独占全屏或特殊系统层。

## English summary

**Version 1.4.1 is an archived test version, superseded by the [1.4.2 release](v1.4.2.md).** The feature descriptions and verification results below are retained as historical records.

New features include streaming local chat with `tobestyledintro/qwen3.8-9b-distill:latest`, an editable username, conversation history with confirmed deletion, message copying, and optional read-aloud replies. Automatic reading defaults off; a reply can be read manually without changing that setting. Closing the chat window leaves the pet running. The persona is bundled from [electron/chat-persona.md](../../electron/chat-persona.md).

First-run setup automatically prepares Ollama, the roughly 6.7 GB chat model, and the roughly 5.7 GB speech runtime. Embedded Python and voice assets, roughly 246 MB, are bundled. Chat and voice setup have separate progress and readiness, cancellation where supported, and retry. Downloading and extracting do not load the speech model or enable automatic reading.

The speech worker reuses the same emotion model, releases it after 45 idle seconds, and caches at most eight replies/24 MiB in memory. On the tested CPU, cold loading or emotion changes take about 25 seconds, while warm replies reach first audio in about 1.8–2.4 seconds. Chat speech pauses other recordings; pet clicks may still show silent captions.

PR #6 body regions follow the four poses, motion, and scale. Head, face, and hands select blush, wink, heart eyes, or smile; body and legs select surprise or blush; props select smile. Ordinary expressions hold for 1.8 seconds without rerolls. A fifth click within three seconds takes priority with anger for about 2.6 seconds and a three-second click cooldown. Transparent gaps and visible decorations are excluded.

Version 1.4.1 fixes the pet falling behind ordinary apps when Always on top and Taskbar in front are enabled. A secondary taskbar could retain its topmost flag while sitting below ordinary applications, causing the pet to be placed behind them as well. Recovery after another topmost app covered the pet is also fixed.

The fix checks actual window order and restores **taskbars → pet → ordinary apps**, correcting only visible, already-topmost Windows Shell taskbars and the app's own windows. Taskbar geometry, visibility, and keyboard focus are preserved. Caption and cursor-trail windows retain their relative order, and disabling always-on-top or switching modes restores the current setting. This does not promise precedence over the secure desktop, exclusive fullscreen, or special system layers.

The 1.4.1 installer, portable EXE and checksums have been removed from the current `main` branch; historical source commits remain available. No 1.4.1 GitHub Release was created. Use the [1.4.2 download and upgrade instructions](v1.4.2.md#下载与升级) for the current app, including its chat-backend migration requirements. The [historical 1.3.0 portable release](https://github.com/ActorF/Elysia_desktop_pet/releases/tag/v1.3.0) remains available; it has no text chat or reply read-aloud, but includes daily greetings and recorded click responses.
