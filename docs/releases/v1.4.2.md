# 1.4.2 测试版更新说明

**1.4.2 是测试版，尚非正式版。** 本地修复基于 `version-control` 的 `6f7e6ac`，补足手动朗读复用、长消息上下文及 Visual C++ 运行库。修复后的安装版、便携版与 SHA256 放在本地 `release/`；尚未推送这些修复，也未创建 1.4.2 GitHub Release。下列远程链接仍对应修复前的分支安装包。

本版修复“本地语音环境已就绪，但点击 Read Aloud 提示暂时无法朗读”的问题，并把默认聊天后台从 Ollama 改为程序自行管理的 llama.cpp。1.4.1 已有的桌宠外观、身体部位互动、日常录音、聊天记录与设置继续保留。

## 手动朗读修复

“语音环境已就绪”表示资源已准备好，播放还要通过勿扰、音量和桌面状态检查。此前 Windows 的忙碌通知状态可能把普通聊天窗口也判为不宜播放，最终只显示笼统错误。

- 明确点击回复下的 **Read Aloud／朗读** 时，普通全屏或系统忙碌状态不再阻止该次播放；在合成期间切换前台窗口也不会仅因此取消。
- 手动朗读仍遵守勿扰、静音、锁屏、休眠和屏幕监测尚未就绪等限制。请求失败时显示具体原因，方便在“语音”页调整。
- 自动朗读默认关闭，单条手动朗读不会改变该开关。自动朗读与自动问候保留屏幕状态限制；普通自有窗口造成的忙碌误判也已修正。
- 手动朗读结束后保留工作进程供短时间内的下一条回复复用，默认空闲 45 秒后释放。关闭自动朗读不会误杀刚完成手动请求的空闲模型；勿扰、静音、锁屏等限制及关闭聊天仍会释放资源。
- 发送新消息、停止、关闭聊天或退出会取消对应朗读并释放资源。播放期间开启勿扰或静音后，不应出现迟到的补播。

首次加载语音模型可能需要较长时间。“环境就绪”不表示模型已驻留内存，看到准备或合成状态后请等待；不同电脑速度不同。联合检查分别记录首次和后续不同文本的朗读耗时，并检查是否复用了同一个工作进程。

## 默认聊天后台改为 llama.cpp

程序使用固定版本 llama.cpp `b11669` 和 Qwen3.8 9B Q4_K_M GGUF 模型。运行包约 32 MB，聊天模型约 5.8 GB，均按固定来源和 SHA256 校验。聊天运行时和模型分别存入用户数据目录下的 `chat-runtime`、`chat-models`，不需要安装系统聊天服务。

程序隐藏启动自己的本地服务，模型加载完成并通过健康检查后才报告聊天就绪。退出时清理自己启动的服务与子进程，下次打开会使用已保存资源重新启动，不重复下载有效文件。聊天和语音环境各有进度、取消、重试及就绪状态。

默认地址为 `http://127.0.0.1:18434`，模型别名为 `elysia-chat`，使用 OpenAI 兼容的 `/v1/chat/completions` 流式接口。保留完整角色设定、用户名和近期对话，运行上下文恢复为与 1.4.1 相同的 16384 token，默认关闭模型思考输出。原先会超过 8192 token 的 8000 字中文回归样例已纳入真实模型检查；输入长度仍为最多 8000 个字符。只有旧版默认 Ollama 本地地址与默认模型的组合会自动迁移；无关的自定义设置保留，自定义服务需支持上述兼容接口，程序不会自动回退调用 Ollama。

聊天首次配置以及旧资源再次启动时，会从程序随附的语音资源包中单独准备 Visual C++ 运行库。整包与六个选定文件均按固定 SHA256 校验，四个 DLL、原许可和来源声明部署到 `chat-runtime/`。不需要先完成语音模型下载，不安装系统运行库，不申请管理员权限。运行库资源缺失或损坏会显示对应错误；重试可补齐或重新准备这些文件。

可识别的独立显卡使用 Vulkan，并为其他应用预留显存；未识别到合适设备时选择 CPU。CPU-only 路径、不同显卡和较低内存电脑的实际启动及速度仍需验证，不能把当前电脑的结果视为通用性能保证。

独立 Python 和语音资源约 246 MB，随程序携带；GPT-SoVITS 运行环境约 5.7 GB，首次配置时准备到 `voice-runtime`。准备资源不会自动开启朗读，也不会加载声音模型。普通文字聊天在自动朗读关闭时不启动声音模型。

## 验证结果与限制

- **437 项单元测试全部通过，无失败或跳过**，包含手动朗读完成后的同步状态通知、工作进程复用、权限变化、运行库升级与完整性检查。
- 真实 llama.cpp 使用完整人设生成中文回复，并成功处理原先报错的 **8000 字中文样例**。此次普通回复约 **3.83 秒**，长消息约 **3.73 秒**；测试只使用隔离历史和合成内容。
- 旧版已准备资源自动补齐 Visual C++ 依赖，首次启动约 **11.57 秒**；检查 Windows 进程模块，确认必需的 VC DLL 实际从 `chat-runtime/` 加载。未依赖语音环境先部署，也未修改系统运行库。
- 保持聊天模型驻留、关闭自动朗读并模拟全屏状态，连续两条不同文本使用**同一个语音工作进程**。首次语音加载与合成约 **41.09 秒**，下一条约 **2.91 秒**，生成 WAV 后模拟播放完成，没有播放测试录音。
- 退出清理及从磁盘再次启动通过；再次启动约 **8.41 秒**。两次退出均未遗留所属进程，没有强制清理无关进程。以上耗时只代表这台电脑本次测量。
- 重新构建后的安装版、便携版进行完整 `verify:release` 与 `verify:setup` 检查，覆盖桌面、语音、互动、聊天及便携版重复启动，共 **9 次包内运行**；安装器的 **69 项资源**与便携版一致，54 条已确认录音原字节保留。

另一台电脑曾记录 `Both taskbar modes retain app topmost` 隐藏窗口断言失败，且在 1.4.1 复现。本机完整检查通过，未复现该失败；仍保留可见桌面、多屏与任务栏顺序的人工验收步骤。

本机通过正式配置流程部署并启动了资源，并验证旧资源升级；**尚未在干净 Windows 实机或虚拟机上完成全部大型资源从零下载、安装、系统重启的全链路验收**，也未完成 CPU-only 实机性能验收。实际 DLL 加载路径检查证明本次运行使用随包部署的运行库，不等同于完整干净系统验收。报告、合成对话、WAV 与环境日志均保存在本地忽略的 `artifacts/`。

## 第二台电脑验收清单

请记录 Windows 版本、CPU、内存、显卡与驱动、所测安装版或便携版，以及失败发生在哪一步。测试时使用新建的测试对话；无需提交个人聊天记录或完整用户目录。

1. **文件与校验：** 测试此次本地修复时，使用本地 `release/` 中的 1.4.2 安装版或便携版，并携带对应 SHA256；本页远程下载尚未包含修复。用 `Get-FileHash -Algorithm SHA256 <文件路径>` 校对后退出旧版再启动。
2. **干净首次运行：** 在尚未配置该程序的 Windows 测试账户或干净机器上打开程序，不预装 Ollama。确认聊天与语音分别显示下载、校验、部署进度，取消后可重试；准备完成前不误报就绪。不要为此删除已有账户的正式数据。
3. **真实聊天：** 等待聊天模型就绪，发送一条简短中文消息，再追问上一条内容；确认逐步显示回复、停止有效、没有思考标记混入正文。关闭聊天后桌宠继续运行，重开聊天仍有测试记录。
4. **重启系统后再打开：** 退出程序并重启 Windows，再手动打开 1.4.2。确认已准备资源不重复下载，聊天服务自动恢复就绪，能继续对话；这里检查的是打开应用后的模型启动，不是新增开机自启。
5. **单条朗读：** 保持自动朗读关闭，点击回复下的 Read Aloud。允许首次模型加载等待，确认最终实际出声，自动朗读开关仍关闭；合成时切换普通前台窗口后仍能完成。分别检查停止、发送新消息、关闭聊天能中止旧朗读。
6. **勿扰与静音：** 开启勿扰后点击朗读，应显示明确原因且不播放；关闭勿扰后再试可恢复。将音量设为零应同样拒绝，恢复音量后可重试；播放期间开启勿扰或静音应停止，不迟到补播。锁屏／休眠恢复后检查状态能够恢复。
7. **退出与数据保留：** 从托盘退出，确认该程序启动的 llama.cpp 与语音工作进程退出。再次打开，确认位置、装扮、用户名、偏好与测试聊天记录保留；便携版重复打开不破坏正在运行实例。
8. **CPU-only 路径：** 在没有受支持独立显卡的测试机器上完成配置、聊天、单条朗读、退出与再次启动，记录启动和回复耗时、内存占用及错误。不要仅凭显卡机器成功就勾选此项，也无需为测试禁用日常机器的显卡。
9. **桌宠原有功能：** 在可见桌面检查移动、缩放、设置、摸头／戳戳、流光、日常录音，以及“桌宠在前／任务栏在前”。有多屏时分别检查任务栏顺序，并关注上述隐藏窗口断言对应的实际行为。

## 源码与复现命令

源码使用 `version-control` 分支。克隆完整 EXE 需要 Git LFS；直接下载程序不需要。自行构建需要 Windows、Node.js 22 或更新版本，以及已准备的 `build-resources/voice-bootstrap/` 语音构建资源。

```powershell
git lfs install
git clone --branch version-control https://github.com/ActorF/Elysia_desktop_pet.git
cd Elysia_desktop_pet
git lfs pull
npm ci
npm test
npm run test:chat
npm run test:chat-native
npm run make:release
npm run verify:release
npm run verify:setup
```

完整桌面检查仍为 `npm run test:smoke` 与 `npm run verify:release`，应保留失败信息，不能用聊天专项结果替代。真实模型与语音联合检查使用 `npm run test:chat-runtime`，需要已部署资源并先退出占用端口的桌宠；环境变量、其他检查和 CI 说明见[验证说明](../verification.md)。构建命令不会自动推送或创建 GitHub Release。

## English summary

**1.4.2 remains a test build.** The repaired installer, portable executable and checksums are local in `release/`. The remote downloads above do not yet include these fixes, and no GitHub Release has been created.

The app now manages a hidden llama.cpp server and a pinned Qwen3.8 9B Q4_K_M GGUF model. It starts the server with the app, releases its processes on exit, and reuses prepared resources on the next launch. Ollama is no longer required or contacted. Only recognized old default connections migrate; custom settings, preferences, and chat history remain intact.

Manual Read Aloud works with automatic reading disabled and retains its worker for the next reply until the idle timeout. Do not disturb, mute, screen lock, suspend, window closure and screen-monitor readiness still apply. The chat context is restored to 16384 tokens. Pinned Visual C++ libraries and their license/notice are prepared beside llama.cpp from the existing bundled resource archive, without a system installation.

All **437 unit tests** passed. Real chat accepted the previously failing 8000-character fixture with the full persona. Two different manual replies reused one speech worker: about 41.09 seconds for the initial load and synthesis, then 2.91 seconds for the next text. Actual process modules confirmed application-local VC DLL loading. Full package checks, portable relaunch, installer-resource comparison, restart and process cleanup passed. Test audio was generated silently.

The earlier PC reported a hidden topmost assertion failure that also reproduced on 1.4.1; it did not reproduce in this PC's full checks. Clean Windows installation and operating-system reboot, CPU-only performance, and visible desktop ordering remain separate verification items. Reports and test audio stay local.
