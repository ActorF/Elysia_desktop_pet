# 本地模型配置错误分类

本文用于开发、故障定位和 issue 处理，覆盖聊天模型与语音环境的检测、下载、校验、解压、环境检查和服务启动。错误定义以 electron/setup-diagnostics.cjs 为准；这是研发对照，不是版本更新说明。

## 诊断字段

每个配置诊断包含 code、scope、stage、summary、action、retryable 和 details。scope 区分 chat 与 voice；stage 标明失败阶段。错误编号用于稳定定位，不随界面措辞变化。已使用的编号不能改作另一种含义。

details 只接受受限字段：HTTP 状态、退出代码、系统错误代码、相对缺失文件列表及数量、实际和预期的安装标记版本，以及本步骤需要和当前可用的磁盘字节数。缺失列表最多展示 20 项，总数可单独保留。不包含请求 URL、签名参数、令牌、响应正文、异常栈、绝对路径、聊天记录或用户凭据。

设置中的“复制错误信息”由主进程重新构造白名单报告，另含报告格式版本、生成时间、程序版本、运行模式、组件和当前阶段。界面只能请求复制聊天或语音诊断，不能传入任意剪贴板正文。操作被拒绝时的单次提示仅在对应状态仍未变化时有效；新的检测结果或恢复状态会取代它，延迟返回的旧结果不得覆盖新状态。

## 证据与恢复原则

- 明确的 diagnosticKind 优先；否则使用最多 6 层、去循环的 cause 中已知系统错误代码。unknown、network-unknown、storage-io、integrity-unknown 不覆盖更具体的系统证据。
- 不根据异常文字猜测根因。只有 ENOSPC 或 EDQUOT 等明确系统证据才报磁盘不足；解压进程退出、Python 检查失败、服务退出不能自动等同于磁盘或内存不足。
- HTTP 401/403、404/410、429 和 5xx 分别归为访问拒绝、发布资源缺失、限流和服务器异常；没有有效整数 HTTP 状态时不猜具体原因。
- 用户主动取消属于 cancelled 状态，不是网络超时或资源损坏。取消后保留可续传部分。
- 已有目录或旧版本资源不能因为一次检测失败就当作全新安装。缺完成标记、标记损坏、资源版本不匹配和必需文件缺失必须分开处理。
- 未验证的目录不自动删除、覆盖、补造完成标记或跳过校验。先保留资源和下载缓存，再根据具体证据决定恢复动作。
- 重新检测不能只清掉错误文字。相同条件仍存在时保留对应诊断；有新证据表明环境恢复后，才清除该错误。检查文件存在不能证明网络故障已经恢复。
- 未能归因的故障保留 unknown，记录可安全提供的阶段和错误编号，等待进一步诊断。

## 已定位的资源包兼容问题

1.4.5 的语音压缩包路径检查误把合法文件名中的 `#` 当作非法字符。固定的 GPT-SoVITS 资源包含有 `runtime/Lib/site-packages/pandas/tests/io/data/legacy_pickle/1.2.4/empty_frame_v1_2_4-GH#42345.pkl`，因此即使下载和 SHA256 校验成功，也会在读取文件列表时报告 `EXT-106`，尚未开始解压。这类报错不能据此归因于网络或用户安装路径。

修正后的压缩包检查、安装记录检查和诊断脚本统一接受文件名中的 `#`；绝对路径、路径穿越、链接、备用数据流和 Windows 非法文件名仍会拒绝。重试优先使用已有的已校验下载缓存，不需要为这个问题删除或重新下载完整资源包。此处记录的是源码修复；对方实际运行版本和错误编号仍应以复制的诊断报告为准。

Windows 上还观察到解压后的暂存目录移动短暂返回 `EPERM`，同一路径、文件字节和权限未变时，等待后可成功；没有证据将它归因于某个安全软件或仅归因于路径长度。这次移动现在只对 `EPERM`、`EACCES`、`EBUSY` 最多重试四次，总等待上限 500 毫秒，支持取消。每次移动前重新核对暂存目录身份和目标不存在；发生冲突会停止并保留暂存目录，永久失败仍保留实际系统错误。此重试不改变正式环境切换事务。

## 聊天朗读后新增盘符

固定语音资源中的 `managed_gpt_sovits.py` 原先通过 `DefineDosDeviceW` 为模型进程创建临时盘符，用于让 Python 3.9 加载原有运行库。桌宠在停止、退出或空闲释放时直接结束桥接进程，Windows Job 会结束模型进程，但不会执行 Python 的盘符清理；重新启动语音时可能再次分配盘符。这里的盘符是同一卷的别名，不是整盘数据的复制；它属于语音启动生命周期问题，与聊天文本、下载来源无关。

桌宠桥接脚本改为借用已经挂载的 C–Z 盘符，必须同时匹配原受保护路径的卷标识和唯一原生设备目标。父进程与独立语音进程同时接受 C 盘，原文件校验、进程归属和路径检查继续保留。没有匹配盘符时停止启动，不回退创建新盘符。适配只在进程内进行，不改写已下载的语音文件，也不移除用户已有盘符。旧版本遗留盘符没有可靠的归属记录，不能仅凭盘符字母或指向同一卷就批量删除。

| RUN-205 | server-protocol | 服务启动 | 本地服务响应与预期的聊天模型不匹配。 | 核对端口上的服务和模型，避免同时运行冲突的旧版服务。 | 否 |
| RUN-206 | memory-unavailable | 服务启动 | 系统报告可用内存不足。 | 关闭占用内存较多的程序后重试，无需重新下载模型。 | 是 |
| MODE-101 | preview-disabled | 检测 | 本地测试模式不允许下载或安装资源。 | 此模式只复用已有资源；请先查看已有环境的诊断结果。 | 否 |
| MODE-102 | preview-resources | 检测 | 本地测试所需的已有资源不完整。 | 先核对现有安装状态；本地测试模式不会重新下载或安装。 | 否 |
| SETUP-999 | unknown | 检测 | 配置失败，具体原因尚未确认。 | 复制错误信息反馈，保留现有资源和下载缓存。 | 否 |

## 旧版资源的恢复流程

设置中的“修复语音环境”是显式操作。普通检测和启动时的安装尝试仍保留未识别目录，检测本身不触发重建。本地预览模式不提供修复、下载或安装操作。

修复先验证缓存及随程序提供的安装包，只有缺少有效安装包时才下载，并继续使用断点缓存。完成记录缺失、损坏、格式或资源版本不符、必需文件缺失均可通过重建恢复。已有目录不会仅凭文件存在就补造完成记录，也不会执行其中未经确认的 Python；新环境使用校验过的安装包独立构建并检查完整性。

下载前检查待下载部分所需空间，解压前按压缩包文件清单检查展开空间。构建完成后，旧语音目录在同盘改名为 voice-runtime.backup-UUID，再换入新目录。备份保持原字节，不复制旧环境，也不自动删除。聊天运行环境使用同样的提交与恢复机制，旧目录保留为 chat-runtime.unverified-UUID；完整 GGUF 可重新计算 SHA256 后重建校验记录，无需重新下载模型。

提交使用单独的持久事务记录，限定组件、目录名及文件身份。换入失败会尝试回滚；若回滚尚未完成，保留事务记录和暂存目录，下次安装或修复继续恢复。事务记录先写入并同步，再以不覆盖已有文件的方式原子发布；进程在目录切换期间退出后也能识别当前阶段。未知或被外部替换的目录不覆盖。普通“重新检测”保持只读，不处理待提交事务。

修复期间暂停使用本程序管理的语音环境，释放本程序自己的朗读进程，避免它占用待切换目录；恢复上次中断的事务也必须等待旧进程退出，聊天运行环境同样适用。未确认退出时，不移动或回滚仍可能被使用的目录，保留事务和资源并报告 FS-103。外部程序占用导致的失败仍保留原资源并提供具体错误信息。

Windows 短暂拒绝目录改名时，提交和回滚只进行有限次数的短暂重试。每次重试前重新核对事务记录、目录身份和所在阶段；出现不同目录或记录变化立即停止，不覆盖后来出现的文件。

取消或超时发出终止请求后，必须确认子进程确实退出。未能确认退出时保留其暂存目录，并阻止再次启动同一资源的配置；收到迟到的退出事件后，只有目录身份仍匹配才可清理。聊天服务和语音进程也遵循这一规则，避免重试时叠加多个模型进程。正常结束朗读先关闭输入管道，让语音运行环境释放资源，再使用有界强制终止作为后备；修复和应用退出等待这一步完成。

下载缓存、断点文件和发布目标分别核对文件身份，不能仅凭长度判断仍是原文件。完整文件校验后以不覆盖目标的方式发布；Windows 不支持硬链接的文件系统使用同卷、按文件句柄重命名，不复制大文件。目标已存在、源文件改变或权限不足不会退回覆盖写入。容量检查在已确认归属的坏缓存处理后、真正请求下载前执行，按剩余下载字节计算。

多个资源源仍使用相同的固定大小及 SHA256，连接失败、服务器错误和不完整传输按下载策略切换或恢复；更换来源不降低内容校验要求。聊天和语音共用静态的 Hugging Face 官方下载节点名单，覆盖欧洲、亚洲及 GCP 节点，避免两套名单不一致而拦截合法跳转；名单变更须核对官方资料，不在运行时自动放开陌生域名。地区网络、代理、路径和解压问题应分别依据 NET、FS、EXT 等编号处理，不能统一归因于代理。

最后一个下载源断连或停在响应结束标记前时，如果断点文件已经收齐规定字节，仍会先检查 SHA256；只有完整校验通过才提交。部分文件、超长文件、校验失败、用户取消和总等待时间到期都不能被当作成功。自有聊天进程启动期间，健康检查或模型列表的临时传输失败按原启动时限继续重试；完整但错误的响应仍视为协议问题，外部进程占用端口也不会放行新服务。

## 排查顺序

1. 收集运行版本、发生阶段、错误编号和已过滤的 details；版本不确定时先记录“未知”。
2. 检测到现有语音目录但安装不完整时，使用 scripts/diagnose-voice-setup.ps1 生成只读报告；报告仅新建诊断文件，不修改模型。
3. 区分首次安装、更新后故障与曾经成功后缺文件，核对安装完成记录与缺失路径。
4. 网络问题保留断点缓存；目录或标记问题先确认资源归属；服务启动问题不要先要求用户重新下载模型。
5. 处理后重新检测，并按故障类型验证相应阶段真正恢复。
