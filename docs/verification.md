# 验证说明

本文件说明 **1.4.2 正式版** 的验证范围。用户已确认修复后的程序人工测试全部通过，并授权晋升正式版。修复包含手动朗读模型复用、16384 token 聊天上下文以及程序独立部署的 Visual C++ 运行库。源码、安装版 `release/Elysia_desktop_pet-1.4.2-setup.exe`、便携版 `release/Elysia_desktop_pet-1.4.2.exe` 与 SHA256 通过 `main` 分支提供；本次不创建 1.4.2 GitHub Release。变化与下载入口见 [1.4.2 更新说明](releases/v1.4.2.md)。报告保存在本地忽略的 `artifacts/`。

正式版通过 **437 项单元测试**、真实 llama.cpp 中文与 8000 字消息、同一语音工作进程的连续手动朗读，以及完整包内检查。安装版的 69 项资源与便携版一致，9 次包内运行包含桌面、语音、互动、聊天和重复启动。另一台电脑曾在 1.4.1／1.4.2 触发隐藏置顶断言失败，本机完整检查未复现；可见桌面检查步骤保留用于后续跨环境回归。干净 Windows 从零安装、系统重启和 CPU-only 性能未作为本次已完成项目；1.4.1 历史结果见其[更新说明](releases/v1.4.1.md#验证范围)。

`npm run make:release` 同时生成便携版与安装版；`npm run verify:release` 校验完整文件清单、源码字节、原录音、语音资源包摘要、更新配置及隐藏窗口行为，并验证重复启动不会删除现有实例的临时文件。`npm run verify:release -- --chat-only` 只运行聊天相关包内检查与重复启动检查，不能替代完整命令。`npm run verify:setup` 核对安装器中的程序和资源与已验证的便携版完全一致。所需语音构建资源保留在被忽略的 `build-resources/voice-bootstrap/`，不依赖旧样本或草稿目录。

`npm run test:chat` 验证消息复制、单条朗读、左右历史布局、删除确认及自动配置进度；`npm run test:chat-native` 使用独立用户配置和模拟推理服务核对真实 IPC、流式回答、语音复用、勿扰拦截、关闭释放和删除记录的持久化。`npm run test:chat-runtime` 使用已准备资源验证真实 llama.cpp 生命周期、中文回复、模型驻留时的真实语音合成与再次启动；`npm run test:chat-tts` 单独测量语音冷启动、暖模型、缓存和进程清理，两者均生成音频但不播放。关闭自动朗读时普通聊天不启动声音模型，用户主动点击朗读可以单独播放。

首次安装逻辑已覆盖固定下载来源、SHA256 验证、取消、重试与自动部署；本机已通过正式配置流程部署 llama.cpp，可移动语音环境已实际合成验证。聊天与语音各自就绪，聊天只有在模型加载并响应健康检查后才报告就绪。尚未在全新 Windows 实机或虚拟机中完成全部大型资源的首次下载安装，不把模拟安装检查或已有资源启动表述为该项验收。

- Windows + Edge 运行设置、聊天及点击互动浏览器回归。结果和截图作为 `browser-test-reports` 附件保留 7 天；上传范围仅限三个测试专用目录。

`main` 的 [Protect main 规则](https://github.com/ActorF/Elysia_desktop_pet/rules/25894047) 禁止强制推送和删除，没有豁免用户。普通推送仍可使用；当前未强制 Pull Request 审批或将 CI 设为合并门槛。

## llama.cpp 聊天与手动朗读

默认服务地址为 `http://127.0.0.1:18434`，模型别名为 `elysia-chat`，通过 `/v1/chat/completions` 接收 OpenAI 兼容的 SSE 流。测试覆盖分块 UTF-8、流式事件边界、结束标记、失败、停止和历史持久化；请求保留完整角色设定、用户名及近期对话。只有识别到旧版默认 Ollama 地址和默认模型组合时才迁移，自定义配置保留，程序不会回退调用 Ollama。

运行时和模型分别保存在用户数据目录的 `chat-runtime` 和 `chat-models`，语音资源保存在 `voice-runtime`。程序隐藏启动自己管理的服务，退出时清理所属进程，下次启动复用已校验资源；不依赖系统 Ollama 服务或新增系统启动项。当前选择可识别的 Vulkan 独立显卡并预留显存，未识别到合适设备时选择 CPU；CPU-only 实机速度和完整启动仍需单独测试。

手动朗读应在自动朗读关闭时仍可启动，并跨普通全屏／系统忙碌状态变化继续工作。完成后的空闲工作进程保留该请求的手动来源，下一条不同文本可直接复用；默认 45 秒空闲超时后释放。勿扰、静音、锁屏、休眠、监测未就绪及关闭聊天仍会释放资源。自动朗读和自动预热不继承手动权限。回归覆盖声道占用时同步取消、完成后同步状态发布、复用、空闲限制变化与超时。

`tests/chat-runtime-dependencies.test.cjs` 用小型 ZIP 夹具验证运行库成员选择、完整性、取消清理与修复，不依赖本地大型资源，适合 Windows CI。真实资源验证还核对微软签名、x64 架构、101 条 VC 导入依赖，以及进程实际加载的 DLL 路径；许可证和来源声明随 DLL 部署。旧资源的启动路径自动补齐这些文件，聊天模型无需重新下载。

真实联合检查需要已部署的模型和语音资源。先从托盘退出桌宠，避免现有服务占用端口；以下命令不会下载模型，不会修改正式聊天记录，也不会播放测试音频：

```powershell
$env:ELYSIA_CHAT_USER_DATA = Join-Path $env:APPDATA 'Elysia Desktop Pet'
$env:ELYSIA_VOICE_PROJECT_ROOT = Join-Path $env:ELYSIA_CHAT_USER_DATA 'voice-runtime'
npm run test:chat-runtime
```

该检查隐藏启动真实服务，确认 VC DLL 实际从 `chat-runtime/` 加载，随后在隔离历史中发送中文短句和原先超出 8192 token 的 8000 字回归样例。保持聊天模型驻留，关闭自动朗读并模拟全屏状态后，连续合成两条不同的手动朗读文本，验证 WAV 及同一个工作进程的复用。最后释放进程、从磁盘再次启动服务并检查退出清理。报告、测试回复与 WAV 只留在 `artifacts/chat-runtime-check/`，其中分别记录冷启动与暖模型耗时；不播放测试录音。

`npm run test:chat-model` 连接已经运行的默认聊天服务验证中文多轮回复；`npm run test:chat-tts` 使用 `ELYSIA_VOICE_PROJECT_ROOT` 指定的环境单独验证语音。它们与上述联合检查有不同的前置条件，不要并行启动多个真实模型检查。换机与跨环境回归步骤见 [1.4.2 回归参考](releases/v1.4.2.md#跨环境回归参考)。

## 表情、形态与动作

- 默认脸与十种表情可独立切换，再次选择同一表情恢复默认脸。
- 猫猫与眼镜是独立开关；四种动作互斥，切换表情或装扮保留动作。
- 检查眼形、嘴型、眨眼、道具遮挡以及各种组合的面部合成。
- 使用实际 WebGL 画面检查头发、刘海、衣摆与双腿轻摆；检查固定的脸部、耳朵与道具区域。
- 预览截图与待机录像供人工核对画风、轮廓和动作衔接。

## 托盘、缩放与窗口

- 托盘左右点击均打开原生菜单，菜单包含“设置”“打开聊天框”和“退出”三项。托盘图标为透明底粉色图案，检查边缘与裁去多余留白后的可见效果。
- “设置”打开独立窗口，与人物同时存在；重复打开复用同一窗口，关闭后可以重开，人物不会退出。
- 设置窗口无系统标题栏，顶部空白区域可拖动；最小化、最大化／还原、关闭三个 SVG 图标为可点击的非拖动区域。窗口状态通知同步最大化／还原图标和无障碍名称。
- 移动、调整或关闭设置窗口不移动人物、不重新加载人物页面，也不替换人物画布。人物穿透状态不影响设置窗口操作，找回操作会恢复人物交互。
- 外观、动画、桌面、互动、语音、聊天、聊天记录七个页面覆盖日常设置；快捷键或其他入口造成的状态变化会同步到设置窗口。正式页面不出现样本标签、试听列表或模拟触发按钮。
- 正式配置使用 `%APPDATA%/Elysia Desktop Pet/`，保留位置、大小、装扮和偏好。覆盖从本地 1.3 样本补入缺失新选项及语音历史的情况，并确认不覆盖正式目录已有值；没有可迁移值时采用默认值。
- 只有按住人物上的鼠标右键再滚动时缩放；释放、失焦和取消手势后停止缩放。
- 连续滚轮输入不丢失，迟到的异步回复不覆盖较新的设置。
- 覆盖 1%、普通尺寸和超大尺寸，验证光标锚点、画布预算、缩小后的清屏和恢复 100% 功能。
- 覆盖连续拖动、跨 DPI 屏幕、四边出屏、窗口恢复与置顶维护。

“桌面”页包含“任务栏层级”选择。1.4.1 修复“始终置顶＋任务栏在前”时副屏任务栏实际顺序落后导致桌宠被放到普通应用后方，以及其他置顶应用遮挡后未恢复的问题。维护目标为可见任务栏在桌宠上方、桌宠在普通应用上方；保留字幕、流光等辅助窗的前后顺序，并在关闭置顶或切换模式后恢复当前设置。

`taskbar-layer-check.cjs` 使用独立透明窗口和独立进程的置顶应用，读取真实 Windows 窗口顺序，检查主、副任务栏排序、外部置顶窗口竞争、自有辅助窗同时存在、原生置顶标志丢失后的恢复，以及隐藏、关闭置顶和切换模式。修复仅校正当前可见且已置顶的真实 Windows Shell 任务栏与自有窗口的 Z 顺序，不改变任务栏位置、尺寸或可见性，不激活窗口或注入输入；检查同时核对当前输入焦点保持不变。报告默认位于 `artifacts/taskbar-layer-check.json`，可通过 `--report` 指定路径。

范围限于普通 Windows 桌面，不承诺覆盖安全桌面、独占全屏或特殊系统层；不会强行显示已隐藏的任务栏或提升被系统取消置顶的任务栏。原生窗口检查与最终包内验收共同验证修复，具体结果以对应报告为准。

“动画”页通过滑块和数值框调节摆动幅度与速度。执行 `node scripts/motion-settings-check.cjs` 检查实际渲染中的幅度、速度变化和关闭摆动的行为；结合 `npm test` 核对 0–200% 幅度、0.25–3× 速度的范围、100%／1× 默认值、上下部位同向运动，以及最大幅度下的网格和点击范围。检查还关注修改速度或切换表情、动作时是否保持摆动进度，并确认眨眼和目光跟随不随摆动速度变化。实际结果以 `artifacts/motion-settings-check.json` 和 smoke 输出为准。

“眼睛跟随幅度”在原有眼睛扭曲算法上增加 0–200% 强度设置，默认 100%。`node scripts/eye-warp-check.cjs` 对比真实 GPU 输出与原始着色器，检查默认效果一致、0% 停止扭曲、加强后的效果、关闭跟随和闭眼表情，以及调节时不额外读取像素或上传纹理。单元测试和隐藏窗口 smoke 覆盖旧偏好迁移、范围约束、持久化，以及目光跟随开关不重置强度。

`node scripts/settings-window-check.cjs` 用浏览器和模拟主机桥接检查真实设置页面：滑块与数值输入的单位换算、范围端点和默认按钮、独立的表情／装扮／动作、大小输入、状态同步和保存失败后的恢复。窗口按钮检查包含三个 SVG 图标、拖动区域排除、最小化／最大化／还原／关闭的请求，以及模拟外部窗口事件后的图标切换。默认尺寸、紧凑尺寸和大窗口的截图与结果写入 `artifacts/settings-window-check/`；浏览器检查不代替原生窗口验收。

`npm run test:smoke` 使用独立配置和隐藏的原生窗口，核对设置、打开聊天框、退出三项托盘入口、设置窗口生命周期、窗口相互独立、隔离的 preload 与 IPC、参数传递和磁盘保存、外部外观更新，以及穿透与恢复操作。检查结束后恢复测试前的偏好和外观。真实用户配置不会被 smoke 测试覆盖。

超大人物通过虚拟尺寸和屏幕可见区域分离来绘制。画布限制为最长边 4096 像素、总面积 800 万像素，不随人物比例无限分配内存。极大缩放采用固定大小的离屏人物及局部采样。

Windows 的原生窗口有最小尺寸限制；1% 人物仍按约 4.2×5.6 DIP 绘制，点击区域投影到人物本身。点击轮廓覆盖动画运动范围，极端放大时不保证逐像素穿透。

## 拖动与点击区域

拖动时主进程直接采样系统光标；普通拖动复用当前画面，松开后继续动画。测试确认拖动不会反复分配画布，外观切换、释放、取消和失焦仍能正确更新。

点击区域由角色轮廓与运动包络生成，透明空白可操作后方窗口。喇叭特效在人物左侧额外预留 140 逻辑像素的绘制空间，人物仍使用原有 600×800 坐标和缩放比例；只将人物与可见特效的轮廓加入点击区域。检查多种外观、眼神方向和动画帧是否仍在原生窗口区域内；缓存命中时不重复读取人物画布。

## 语音、字幕与点击互动

`npm test` 覆盖 12 类日常语音的时间段、活跃判断、优先级、每日次数、20 分钟冷却与跨重启历史，以及生日月日、往年生日记录、返回事件过期和系统时钟回拨。录音必须实际开始播放才消耗自动问候名额或互动轮换；互动各组轮换避免相邻重复。

`npm run test:voice` 在隐藏且静音的 Electron 窗口中加载 36 条日常录音与 18 条互动录音，使用测试时钟验证日常条件。检查完整字幕最多两行、长短句尺寸变化、粉框白底、没有姓名栏与关闭按钮、左右侧选择及多屏可用范围。播放、停止、快速替换、迟到的音频 Promise、退出、锁屏与销毁都不能使旧录音复活；录音结束后才进入约 1.2 秒的字幕尾留。

`npm run test:interactions` 使用实际页面鼠标事件检查头部与身体点击、3 秒内合计五次生气、冷却和表情恢复，确认拖动、右键滚轮与透明空白不计入轻点。互动语音检查还覆盖约 300 ms 的连点合并、当前录音不中断、仅保留一条生气回应、6 秒等待期限及 1.2 秒语音间隔。

设置检查验证点击互动与自动日常问候分开控制，勿扰和静音转为文字回应，关闭点击互动会清除音频、字幕与等待中的回应。生日只保存月日；正式界面只保留正常设置和播放状态，测试工具不暴露给用户。

人工验收时可依次轻点头部、轻点身体，再于 3 秒内混合点击五次。确认表情与字幕匹配、不叠音，拖到屏幕左右两半后气泡方向正确。语音播放中关闭点击互动或开启勿扰，等待超过 6 秒，旧互动不能补播；重新开启后从新的点击开始。

## 鼠标流光与保留时间

`npm test` 覆盖同屏高速移动连续、跨屏断开、负坐标及不同 DPI、窗口尚在加载时保留近期路径、无几何变化的显示器通知不清空轨迹，以及关闭、阻塞、换样式、换时长和销毁后的迟到消息隔离。

三种样式共享生命周期与绘制预算。默认 0.6 秒的外观保持不变；保留时间支持 0.1–5 秒小数，滑条步长 0.1 秒。长时历史使用固定时间桶与密集近期采样，总源点最多 192、平滑几何最多 512、绘制色段最多 64；5 秒设置不能因点数上限退化为不足一秒的尾迹。粒子寿命按时长缩放，到期后画布归零并停止 RAF。

`npm run test:settings` 检查小数输入、范围约束、默认按钮、暂时清空输入框、关闭流光时预设样式与时长、自动保存和重新打开。`npm run test:interaction-settings` 检查实际 Electron IPC 与磁盘持久化，以及三种样式的快速直线、持续折返、中段像素、独立开关、鼠标穿透和时长到期清理。

隐藏窗口可能被 Chromium 降低绘制频率；像素截图接口可能唤醒合成器。因此隐藏 smoke 的像素通过，不能单独证明真实桌面一直可见。可见窗口的回归步骤如下：

1. 刚启动立即快速移动 A→B，确认中间也有轨迹；等完全淡出后再甩动一次。
2. 三种样式各做持续快速左右折返、顺时针画圈和急转弯；确认实际桌面持续显示，而不只是在截图回读后出现。
3. 分别设为 0.1、0.6、1.5、5 秒，确认停下后的消失时间不同。修改时长、换样式和关闭开关应立即清空旧轨迹。
4. 点选、输入和拖动普通窗口，确认流光不拦点击、不抢焦点。跨屏、锁屏及休眠恢复后不连接到旧位置。
5. 关闭点击互动仍保留流光；关闭流光仍可点击人物。重启后开关、样式和时长分别保存。

浏览器压力测试用于比较同一环境下的绘制变化，不作为所有电脑帧率的保证。完整应用中的真实输入、可见透明窗口和桌面合成检查，与自动化测试互相补充。

## 便携包验收

构建前确认 `assets/voice/audio-final/` 中的 36 条日常录音与 `assets/interaction-voice/audio-final/` 中的 18 条互动录音齐全，并与各目录 `final-audio-map.json` 中的编号和 SHA256 一致。打包只使用正式资源目录，不依赖本地样本或 `artifacts/` 中的草稿。

按键云朵的本地检查覆盖最新字符替换、大小写与标点、空格、功能键过滤、关闭清空和一秒过期。喇叭动作额外检查向外移动、全程淡出、切换动作时保留当前字符，以及云朵和扩音弧线的完整运动范围是否包含在原生窗口区域内，动画不逐帧重建窗口轮廓。`npm test` 在 Windows 上还运行真实 Win32 字符翻译与监听生命周期检查，不向用户窗口注入输入。

`verify-package.cjs` 从最终 EXE 提取应用内容，核对文件清单、源码与素材字节、54 条录音及其校验清单、代码许可证和版权说明。随后运行目录应用和便携程序的验收，检查启动、桌面交互、缩放、独立设置窗口及语音资源。具体执行项目和通过状态以脚本输出为准。

验收会核对运行前后的原有桌宠进程，保留用户正在使用的实例。结果与 SHA256 写入 `artifacts/validation-v1.4.2/release-check.json`，校验文件生成在 `release/`。报告、真实环境日志与测试音频保留本地，不随发布包上传。
